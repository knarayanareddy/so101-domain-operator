# SO-101 Domain Operator review

## Scope and verdict

Robot-control implementation/prototype at `3c962ec85f73e97be626d7fa19f3fe08642460c4`. This review inspected numbered-source evidence for the README, package manifest, Pages workflow, bridge requirements, database setup, Vitest config, and selected virtual-test files only. No hardware, simulator, tests, server, install, or deployment was run. Motion, serial-bridge, API-route, and UI implementation bodies remain outside the inspected sample, so physical safety and product claims remain unverified. [Plan](./REMEDIATION_PLAN.md).

## Architecture and product boundary

The sampled README describes four distinct product surfaces: a Next.js control deck, a headless `tools/so101.ts` operator, advisory vision, and advisory sensors, with a three-valued verification ledger for domain outcomes ([README.md:12-17,30-38](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/README.md#L12-L38)). The sampled Pages workflow also states that API routes "cannot exist in a static export" and are moved aside during Pages builds, so the static site is not the full runtime surface ([.github/workflows/pages.yml:27-31](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/.github/workflows/pages.yml#L27-L31)).

## Findings ledger

- **SO-1 — High, unverified risk:** README claims the headless operator has "safety interlocks baked in" ([README.md:13](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/README.md#L13-L13)), but no sampled source here proves independent emergency stop, joint-limit enforcement, fail-safe handling, or command authorization on real actuator paths. Do not actuate without a qualified operator, physical safeguards, and verified read-back.
- **SO-2 — Medium, confirmed static:** the so-called live mission suite is "LIVE (not dry) on the virtual arm" and is skipped unless `LIVE_ALL` is set, while default `npm test` skips it ([src/lib/__tests__/all-missions-live.test.ts:7-11](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/src/lib/__tests__/all-missions-live.test.ts#L7-L11); [package.json:10-12](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/package.json#L10-L12)). Default test success cannot establish real-hardware reachability or even that this extended virtual suite ran.
- **SO-3 — Medium, confirmed static:** the Pages workflow says API routes shell out to a local Python tool and "cannot exist in a static export," so the build temporarily removes them for Pages ([.github/workflows/pages.yml:27-31](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/.github/workflows/pages.yml#L27-L31)). A successful Pages deployment therefore does not prove detect, voice, state, or health services work in the intended runtime.
- **SO-4 — Medium, unverified risk:** `src/db/index.ts` states Postgres is only a "backup" and that `localStorage is the source of truth` ([src/db/index.ts:5-9](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/src/db/index.ts#L5-L9)). Backup completeness, ledger integrity, multi-client consistency, and restore behavior remain unknown from this sample.
- **SO-5 — Informational, historical CI:** the snapshot metadata records a successful Pages deployment for this SHA, but that evidence is limited to static-site publication and is not a hardware or server-mode test (`fleet-hardening-review/publication-evidence/so101-domain-operator.json:1-23`).

## Five-discipline assessment

- **Correctness:** the sampled spec surface consistently says verification is three-valued and that `unknown` is never promoted to pass ([README.md:30-38](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/README.md#L30-L38)). The sampled detector tests reinforce that "A detection is evidence, never permission" and reject motion planning when calibration is missing or targets are out of reach ([src/lib/__tests__/detect.test.ts:13-17,183-209](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/src/lib/__tests__/detect.test.ts#L13-L17); [src/lib/__tests__/detect.test.ts:183-209](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/src/lib/__tests__/detect.test.ts#L183-L209)). None of that proves the same boundary survives every unsampled live actuation path.
- **Automation:** the sampled manifest defines separate `lint`, `typecheck`, default `test`, opt-in `test:live`, and bundled headless operator scripts ([package.json:4-16](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/package.json#L4-L16)). Sampled tests cover countdown behavior under unrelated timer noise, virtual motor protocol/kinematics, and opt-in full mission runs on the virtual arm ([src/lib/__tests__/autorun.test.ts:8-56](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/src/lib/__tests__/autorun.test.ts#L8-L56); [src/lib/__tests__/driver.test.ts:8-97](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/src/lib/__tests__/driver.test.ts#L8-L97); [src/lib/__tests__/all-missions-live.test.ts:7-39](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/src/lib/__tests__/all-missions-live.test.ts#L7-L39)). No test was run in this review.
- **DevOps/operations:** Pages publication is explicitly a static export path with API routes removed, while the sampled DB layer is designed to tolerate builds without `DATABASE_URL` because the browser-side state remains authoritative ([.github/workflows/pages.yml:27-31](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/.github/workflows/pages.yml#L27-L31); [src/db/index.ts:5-23](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/src/db/index.ts#L5-L23)). Bridge dependency provenance is also unresolved from the sampled requirements file, which only sets lower bounds and an extra install note ([public/bridge/requirements.txt:1-3](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/public/bridge/requirements.txt#L1-L3)).
- **OWASP/security:** the sampled workflow comments say API routes shell out to a local Python tool, and the README advertises localhost side channels for YOLO and ESP32-S3 bridges ([.github/workflows/pages.yml:27-31](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/.github/workflows/pages.yml#L27-L31); [README.md:62-69](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/README.md#L62-L69); [README.md:95-96](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/README.md#L95-L96)). Authentication, origin checks, command authorization, input validation, credential handling, and log/data exposure were not inspected in this sample.
- **UI/UX/accessibility:** the sampled README promises a "live arm control" deck and also warns that nothing has run on a physical SO-101 and that Sim Lab does not drive hardware ([README.md:12-17](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/README.md#L12-L17); [README.md:72-85](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/README.md#L72-L85)). Actual stop affordances, simulation/live labeling, keyboard operation, and failure presentation were not inspected.

## Production blockers and owner decisions

Owner decisions are still required for qualified operator assignment, physical stop mechanism, exclusion zone, calibrated hardware limits, permitted missions, authoritative storage, deployment environment, and release evidence thresholds. The sampled README explicitly says nothing has run on a physical SO-101 and that Sim Lab does not drive hardware, so no current document should imply physical validation without a separately authorized supervised acceptance step ([README.md:76-85](https://github.com/knarayanareddy/so101-domain-operator/blob/3c962ec85f73e97be626d7fa19f3fe08642460c4/README.md#L76-L85)).
